## Findings

### R1 — P1: navigation credit can be earned without navigating

Owners: `share/v2_runtime.py:2402`, `share/v2_runtime.py:2203`, and
`share/gen_curriculum_v2.py:4799` / `4816`.

The new M0.L0 and M0.F0 lessons have identical START and TARGET. Their real
grader checks artifact equality and method traces, but never checks
`cursor_goal`. The test replay checks the cursor; the production grader does not.
The exact-path recognizer searches the **raw** trace as an ordered subsequence.
The key budget uses a different, cleaned trace. Submission classification accepts
arbitrary arguments after `write`, including a shell-write command.

For M0.F0, type `:write !true 'j0f*'`, Enter, then `:q!`, Enter. The required
characters occur only as shell-command argument text. The raw trace matches
the required path, while cleanup removes every token and the four-key budget
passes. M0.L0 has the same defect with `:write !true j0`.

Observed evidence:

- Both production `_required_method_error` calls return `None` with an empty
  cleaned edit trace.
- An in-memory `run_edit` integration probe, with filesystem/persistence,
  paired-question, viewer and editor boundaries stubbed, reaches `_complete`
  once for each card and returns 0. The production artifact and method
  decision logic is not stubbed.
- A real clean headless Neovim buffer executed `write !true 'j0f*'` and
  retained its starting cursor at row 1, display column 5. This was not a
  headed tutor credit run; it independently establishes that the accepted
  argument text does not navigate.

Required repair: capture the art-window cursor at the actual submission
boundary and enforce each navigation goal. Match taught commands as executed
Normal-mode operations, not arbitrary command-line text. Restrict submission
cleanup to genuine save/exit operations. Add negative controls for these exact
argument-only traces and for an incorrect final cursor.

### R2 — P2: the JIS branch's exact-transcription claim ignores whitespace

Owners: `share/v2_runtime.py:1382`, `share/v2_runtime.py:1390`,
`share/v2_runtime.py:4106`, and `share/viewer.py:162`.

Every current M10 card lacks `preserve_trailing_whitespace`. Both saved rows
and targets are normalized with unrestricted `rstrip()`. Appending U+3000
followed by U+0020 to **every target row** of M10.01 still compares equal.
This is not exact Unicode transcription or whitespace-preserving export.
The metadata describes M10 as exact UTF-8 transcription; it is narrower in
the actual grader.

Even cards that opt into whitespace preservation lose it in the viewer path:
`watch_your_work`, project preview, and gallery reads use `_read_lines` without
the flag. `lesson_view` also strips the supplied BEFORE rows unconditionally.
A before row `ヽ_ノ` + U+3000 + U+0020 and an after row `ヽ_ノ` produce a
single `yours` view, hiding the whitespace removal. This also affects
explicit M11 whitespace-cleanup lessons, not only prospective JIS authoring.

Required repair: give the proportional track an explicit whitespace contract
and preserve it through grading, checkpoints, preview and gallery. Show
whitespace differences diagnostically without replacing the canonical text.
Add independent half-space/full-space mutation controls at those boundaries.

### R3 — P2: deletion-only viewer diffs can show no change

Owner: `share/viewer.py:210` (also `_changed` at line 168).

With diff enabled and onion disabled, rendering visits only the current
frame's height and current row length. `_changed(['abc'], ['ab'])` marks
coordinate `(0, 2)`, but the renderer never visits it. The rendered output
is just `ab`, with no deletion marker, both with and without ANSI colour.
`_changed(['a', 'b'], ['a'])` returns an empty set, so a deleted whole row is
also absent from the diagnostic. Multiple deleted tail cells collapse to
one marker even when another mode supplies a larger render extent.

Required repair: compute and render the union of previous/current extents
when diff is enabled, independently of onion skin. Record each deleted
position and row. Add tail-deletion and whole-row-deletion controls with
onion disabled; include unequal frame sizes.

### R4 — P2: wide-glyph mismatch positions are mislabeled as columns

Owner: `share/v2_runtime.py:2567`.

`_first_difference` returns a Unicode codepoint index. `_artifact_replay`
labels that index plus one as a column. For TARGET `　⌒ヽ` and YOURS `　⌒ノ`,
the message reports column 3. Under the runtime's own terminal-width model,
the differing glyph begins at display column 4. Neither number is a native
Saitamaar pixel coordinate. A learner following the displayed column can
inspect the wrong place in Neovim's wide-character grid.

Required repair: report a terminal display column using the measured prefix
width, and label character/byte indexes separately when supplied. A future
proportional diagnostic must use the declared font's advance positions and
must name its units.
